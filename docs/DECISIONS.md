# Decisions and working notes

Decisions made where the brief left room, plus enough state for a fresh session to resume.

## Content design

- **Bank size and split (364 items).** Form A 115, Form B 115, drill 134. Each form = the 100-item grid exactly + 15 unscored. The drill pool covers the grid (so a full exam can be built from drill items alone) plus extras weighted toward KGs I, G and L, two Domain V items and two safety items (`kg-extra.json`).
- **Unscored items per form**: by domain 2/2/3/4/2/2 (≈ proportional to 14/14/17/31/12/12). Cells chosen: (I,L) (I,A) (II,B) (II,D) (III,G) (III,I) (III,H) (IV,I) (IV,G) (IV,C) (IV,K) (V,F) (V,B) (VI,E) (VI,M). They are written to the same quality bar as scored items. See `content/blueprint.json`.
- **Allocation** is generated by `scripts/make-allocation.mjs` → `content/allocation.json`; the validator checks each file against it.
- **Writers.** Drafted by separate writing agents from `docs/WRITER_BRIEF.md` and `docs/ITEM_WRITING_GUIDE.md`, then revised three times. Rounds 1 and 2 left keys guessable from the options alone; round 3 (`docs/REVISION_BRIEF_R3.md`) fixed it. See `docs/QA_REPORT.md`. Three early content commits also carry a small script edit.
- **Ethics Code cards.** The brief calls for one card per principle (6) and standard (25). Standard titles and numbering in the 2024 Code could not be verified offline, so the 25 standard cards use descriptive titles (no numbers) and paraphrase substance consistent with the brief's anchors. Verify against the current Code.
- **Citations.** Registry entries give authors, year, title and journal/publisher only. The first draft included volume, issue and pages from memory, against the brief; they were removed. A few AASP-list texts whose exact titles couldn't be confirmed offline (e.g., Gelso 2010, Corey 2020, Parham 2005, Goldstein 2008, Arvinen-Barrow & Clement 2024, Cotterill 2020, Shanmuganathan-Felton & Smith 2022) are deliberately **not** in the registry rather than risk a wrong title.
- **Answer positions** are balanced in storage and also shuffled per sitting at runtime.

## Exam engine

- **Wall-clock timer**: `remaining = duration − (now − startedAt − pausedMs)`. Nothing depends on the app staying open; expired exams are auto-submitted on the next load/foreground, with a "Time's up" notice.
- **Strict** (default): no pause. **Coached**: pause (question hidden while paused) + pacing line vs 47 s/item.
- **Item and option order** are shuffled per sitting (seeded) and stored in the session, so resume is exact.
- **Unanswered = wrong.** Unscored items are recorded as practice attempts but never count toward the exam score.
- **Scaled estimate**: piecewise linear 0→200, target→550, 100→800; target configurable (default 70). Results re-map with the current target.
- **Retakes**: a second sitting of the same form is labelled "not a fresh estimate". A mixed exam that includes previously seen items is labelled the same way, with the count.
- **Hidden items**: excluded from drills and mixed exams. On a form, a hidden item is swapped for an available drill item from the same grid cell, so the form still matches the grid.
- **Form items stay unseen** until that form has been submitted: drills, quizzes, blocks, and mixed exams draw only from the drill pool plus forms already taken.
- **Discarding**: an unfinished exam isn't scored, but items it opened are remembered so a later sitting is labelled not fresh. The form stays locked for drills.

## Study logic

- **Weak areas**: cell weight = grid weight × (1 − smoothed accuracy of latest answers), prior 60% with k = 4. Item priority adds unseen (+2), last wrong (+1.5), unsure (+1), cell weakness, minus recent repeats.
- **Readiness**: blueprint-weighted (domain weights) smoothed *first-try* accuracy → estimated raw and scaled, with a ~90% band; labelled an estimate; shown only after ≥ 60 answers.
- **Spaced review**: Leitner boxes 1/2/4/8/16 days, compressed by `daysLeft/30` (min 0.2×) and capped to the day before the exam. Only missed, flagged, or "not sure" items enter; five correct reviews graduate an item. Cards use the same intervals but stay in rotation.
- **Today cadence**: resume a running exam → set date → Form A (diagnostic) → review the last exam's misses → weak-area drills to the daily target → Form B when ≤ 14 days remain or ≥ 10 days after Form A (min 3 days after) → in the final week, Form B if still untaken (≥ 4 days out), otherwise a mixed exam → last two days and exam day: light review only (cards + short quiz), never a full exam.

## Platform

- **Stack**: Vite 8 + Preact 10 + TypeScript; hash routing and relative base so it works on any static host/subpath.
- **Storage**: IndexedDB (one key per session so exam writes stay small) → localStorage fallback → memory (with a warning). The running exam is also mirrored synchronously to localStorage on every change; on load the newer copy wins. `navigator.storage.persist()` is requested after onboarding.
- **Service worker**: generated at build with a content-hashed precache list; cache-first; a new version waits until the user taps "Update now", and the banner is hidden during exams.
- **Routing**: hash listeners attach at module load and `useRoute` re-reads the hash when it subscribes. The first version subscribed inside `useEffect`, which runs after paint, so a hash change in that window was lost; it surfaced as intermittent E2E failures after a reload. (An earlier commit message blamed WebKit for dropping `hashchange` after reload. That diagnosis was wrong: a listener added by the test did receive the event.)
- **Insecure contexts (LAN preview)**: each capability (service worker, file share sheet, wake lock, async clipboard, storage persistence) is feature-detected; fallbacks are download, `execCommand('copy')`, and plain storage. Settings → "This device" lists what's available.
- **Accessibility scan** runs axe-core in Chromium at the same four viewports because Playwright's WebKit build crashes while executing axe-core (reproduced with axe 4.8.4, 4.10.3 and 4.14.1 on a near-blank page). All functional E2E tests run in WebKit.
- **Icons**: original SVG (ring + rising line), rendered to PNG via Playwright Chromium (`npm run icons`, inside Docker on this host).
- **dist/ is committed** so the tag carries the exact build; `npm run build` from the tag reproduces it byte-for-byte. The zip goes to `release/` (git-ignored).

## v1.1.0 (UX)

- **GitHub Pages:** `.github/workflows/pages.yml` builds, tests and publishes `dist/`; it fails if the committed `dist/` differs from a clean build. Subpath hosting is covered by an E2E test with the service worker.
- **Update banner:** reported only when a new worker installs beside an active one (a first visit could show a dead "Update ready").
- **Install before setup:** on iOS the Home Screen app has its own storage, so onboarding asks for installation before the exam date.
- **Unanswered exam questions** are still scored wrong but are flagged `na` and excluded from "seen", answer counts, mastery and readiness.
- **Scroll restoration:** history entries carry an index, so Back restores the previous scroll position and forward navigation starts at the top.

## v1.2.0 (UX)

- **Review progress:** opening a miss records it and where to resume; the review counts as done when the learner moves on from the last miss (or taps "I'm done reviewing"), not when it opens.
- **Review Back:** a question returns to its list with history Back only when the list is the entry directly below it (tracked by history index); otherwise it replaces itself with the list. A module-level flag could go stale.
- **Exam timer:** one button in every state, so keyboard focus survives the switch to the low-time display; once low it can't be hidden and leaves the tab order.
- **Short screens:** below 500 px tall the navigator is a full-height sheet with the legend scrolling with the grid, and tutor's "I'm not sure" shares the action row.
- **Question sentence:** split from the scenario and set bold in the exam, tutor and review (`QStem`).

## v1.3.0 (delight)

- **Celebrations live inside their card.** Each burst draws on a canvas inside the card it celebrates, clipped to the largest empty right-edge pocket measured from text line boxes and controls; with no room there is no confetti, only the glow and the words. A full-screen or behind-content layer covered text or went unseen.
- **Words carry every reward.** Milestones and the daily goal are lines in the verdict, so Calm, Reduce Motion and VoiceOver get the same reward. A miss never gets confetti; a goal reached on one is a plain green note, announced once inside the verdict.
- **Celebrate once.** Summaries and results celebrate only when fresh and the first time they open (`firstTime`, `fresh`); a "Time's up" dialog holds the moment until the learner opens the result (`holdCelebrations`). Pending bursts are cancelled on every route change.
- **Review is one state machine.** `reviewStep()` (start / continue / resume last / finish) drives Today, In progress and Results. Opening a miss counts as reading it; leaving an item any way (including Safari's back swipe) records that it was left; only "Finish review" finishes, and it plays the review's own moment. Set-aside reviews can still be finished.
- **Pull requests are checked.** The Pages workflow also runs on pull requests to `main` (typecheck, unit tests, clean build matches the committed `dist/`); only a push to `main` deploys.
- **No pressure.** The study-days count only grows ("A missed day just starts a new run"); the goal card says more is optional; the timed exam has no feedback at all; streaks and volume disappear in the final two days.

## v1.4.0 (flash drill)

- **Why.** Learners were surprised how scenario-heavy the app is (362 of 364 items are vignettes, as on the exam). Flash rounds add quick fact recall; they are an add-on, never Today's main action, because fact quizzing helps fact recall more than applied performance (Agarwal 2019).
- **Separate data, no migration.** Flash progress is one new store part, `flash: { srs, days }`. Flash never writes `attempts`, `sessions`, `srs`, `cardSrs`, `settings`, `reports`, `hidden` or `meta`, so readiness, scores, the daily question goal and exam history can't move. Flash study days live in `flash.days` (not `meta.days`) and are only read into the streak. `SCHEMA` stays 1; a device without the key loads it as empty, and nothing is rewritten on first load. Malformed stored flash data is ignored in memory and left on disk.
- **Backups.** New backups include flash and count it separately (the `reviews` count is unchanged). A v1.3.0 backup restores as before with empty flash progress, and the preview warns when that clears progress on the device; a backup whose flash part is damaged still restores everything else. Rolling back: v1.3.0 restoring a new backup brings back every v1.3.0 part and drops flash (its `replaceAll` only writes the parts it knows). A backup made in a v1.3.0 tab that is still open has no flash part.
- **Scheduling.** `scheduleCard` (every entry kept). Only the first answer in a round is graded; the end-of-round retry of a miss writes nothing. Practice ahead (a fact not yet due) never raises a level. "That was a guess" re-grades a right answer as unsure from the entry before the answer. Removed facts' entries stay stored and are ignored. Final days: practised facts only.
- **Stale rounds.** A round stops saving if the data was replaced since it began: `meta.createdAt` (another tab's reset) or the store's `replaceEpoch` (a restore, here or announced by a `replace:` ping). A grade made in another tab before that ping arrives can still land, the same exposure `cardSrs` has.
- **Content.** 225 facts (about 70% multiple choice, 30% true/false), each grounded in one concept card and checked by the validator (`--flash`), a blind answer pass and an options-only pass (Gemini 4 Neon), and a source-support review against the cards (GPT-6.2 Sol); see QA_REPORT. False statements show the corrected true statement first, in bold.
- **Testing note.** The upgrade test (`tests/e2e/upgrade.spec.ts`) serves the previous release's committed `dist/` (extracted by `npm run e2e`) and updates it to this build through the real service worker, with a timed block running and a second tab left on the old code.
- **Follow-ups, not done.** Problem reports for flash facts (reports assume exam item ids); flushing pending writes before "Update now" (an update from v1.3.0 runs v1.3.0's handler anyway); making the clear-then-write restore atomic; cross-tab merging of writes to the same part.

## v1.5.0 (exam time)

- **Why.** Learners asked for practice exams without the 90-minute clock, and with double time for those who get an extra-time accommodation on the exam.
- **Where.** A Time choice (Standard, Double time, Untimed) on the Form A, Form B and Mixed exam screens. Standard is preselected every time and not remembered, so nothing is added to settings. The 23-question exam-pace block stays at exam pace.
- **Stored as one optional session field.** New sittings get `time: 'double' | 'untimed'`; standard sittings are built exactly as before with no `time` field, and existing sessions, attempts and scores are untouched. `SCHEMA` stays 1. An untimed exam is the same exam engine (no feedback until submit) with `durationMs: 0`, which the timer already treated as "never expires" (also in v1.4.0, so an older tab never auto-submits one).
- **Double time counts.** It is an accommodation, so a double-time sitting counts everywhere a standard one does: exam history, the score-gain line, and pace (its own target, 94 s per question, on its results). It is labelled "double time" in history and results, with no caveat.
- **Untimed is labelled, not hidden.** Untimed sittings are scored, count as taken (their questions are seen) and feed the readiness estimate like any practice answers, but carry a note that the score may run higher than on exam day, are left out of the score-gain line, and their answer times are left out of the average pace. With no clock there is no Mode choice (nothing to pause), no time warnings and no pacing line, and an app update may be offered while one is open in the background.
- **Testing note.** The upgrade test now starts from v1.4.0, the release learners have, with flash progress, a running timed block and a second tab on the old code.
